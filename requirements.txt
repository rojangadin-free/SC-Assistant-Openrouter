# Runtime dependencies.
#
# Two rules for this file, both learned from a broken deploy:
#
# 1. Every third-party module the code imports must be listed here. `pip install`
#    succeeding locally proves nothing — a package can be present in your venv as
#    somebody else's transitive dependency and vanish in a clean container.
#    `langchain-openai` and `pinecone` were both imported by rag/chain.py while
#    listed nowhere, so the image would have built and then crashed on startup.
#
# 2. Anything with C extensions is pinned to a version that publishes a manylinux
#    wheel for cp310 (the Dockerfile's Python). Unpinned + a conflicting
#    constraint elsewhere makes pip backtrack through older releases until it
#    reaches one with no wheel, then try to compile it — which fails in the slim
#    image with "Please make sure the libxml2 and libxslt development packages
#    are installed". The traceback names lxml, but the cause is the pin, not lxml.
#
# Verify a change against the container's platform before pushing:
#
#   python -m pip install --dry-run --ignore-installed --target _t \
#     --python-version 310 --implementation cp \
#     --platform manylinux2014_x86_64 --only-binary=:all: \
#     -r requirements.txt
#
# Exit 0 means every package resolves to a prebuilt wheel and the image will
# build. Exit 1 names the package that would need a compiler.

# This pin decides WHICH RERANKER MODELS CAN LOAD, which is not obvious from the
# line itself. It used to be 3.3.1, which held `transformers` on the 4.x line, and
# that is why `cross-encoder/ettin-reranker-32m-v1` failed the image build with
# `ValueError: Tokenizer class TokenizersBackend does not exist` — the model's
# tokenizer_config names a class only transformers 5.x ships, and its config.json
# is `model_type: modernbert`, which 4.x also does not know.
#
# Now on the 5.x line, deliberately, so the ettin reranker configured in
# rag/reranker.py can actually be constructed. Both pins are explicit rather than
# `>=`: sentence-transformers 5.x accepts any transformers 5.x, and letting pip
# choose means the image silently follows upstream releases between builds — the
# next `transformers` minor could reintroduce exactly this class of breakage on a
# rebuild nobody thought was risky.
#
# Verified against the container's platform with the cp310 dry-run at the top of
# this file: both are pure-Python wheels, and the torch they pull (2.6.0) has a
# cp310 manylinux wheel, so nothing needs a compiler.
#
# This pin and DEFAULT_RERANKER_MODEL in rag/reranker.py move together — upgrade
# here first, dry-run, then change the model. tests/test_reranker_model.py fails
# if an ettin id is configured while this sits below 5.x.
sentence-transformers==5.7.0     # cross-encoder reranker (rag/reranker.py)
transformers==5.16.1             # pinned because the reranker's tokenizer needs 5.x
