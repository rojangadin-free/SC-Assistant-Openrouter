# Runtime dependencies.
#
# Two rules for this file, both learned from a broken deploy:
#
# 1. Every third-party module the code imports must be listed here. `pip install`
#    succeeding locally proves nothing — a package can be present in your venv as
#    somebody else's transitive dependency and vanish in a clean container.
#    `langchain-openai` and `pinecone` were both imported by rag/chain.py while
#    listed nowhere, so the image would have built and then crashed on startup.
#
# 2. Anything with C extensions is pinned to a version that publishes a manylinux
#    wheel for cp310 (the Dockerfile's Python). Unpinned + a conflicting
#    constraint elsewhere makes pip backtrack through older releases until it
#    reaches one with no wheel, then try to compile it — which fails in the slim
#    image with "Please make sure the libxml2 and libxslt development packages
#    are installed". The traceback names lxml, but the cause is the pin, not lxml.
#
# Verify a change against the container's platform before pushing:
#
#   python -m pip install --dry-run --ignore-installed --target _t \
#     --python-version 310 --implementation cp \
#     --platform manylinux2014_x86_64 --only-binary=:all: \
#     -r requirements.txt
#
# Exit 0 means every package resolves to a prebuilt wheel and the image will
# build. Exit 1 names the package that would need a compiler.
